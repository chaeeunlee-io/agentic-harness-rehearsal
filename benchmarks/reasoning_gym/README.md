# Reasoning Gym

Training harnesses: `t2`, `miniswe`, `goose`; held out: `aider`. Evaluation uses four attempts per task, reports the trial-pooled mean, and bootstraps over tasks. Serving uses `max-model-len=32768`, the Hermes tool-call parser, and the DeepSeek-R1 reasoning parser.

- There are two difficulty tiers, easy and hard, with 96 test tasks each. Rewards are graded in [0, 1] rather than binary.
- Rehearsal here is transcription: the rehearsal task gives the answer string, and the policy only has to submit it through the t2 harness.
- Gemma-3-4B-it trained on the same distillation datasets as Qwen3-4B, with its own chat template (see the config).

Configuration: `configs/benchmarks/reasoning_gym.yaml`. Published results are in `results/cells.csv` with `benchmark=reasoning_gym`.

## Layout

| directory | contents |
|---|---|
| `harnesses/` | the `DispatchAgent` that picks a harness per GRPO rollout (`rl.agent_import_path` in the config): `harness_dispatch.py`. Evaluation uses harbor's own terminus-2, goose and aider agents and the pinned mini-swe-agent in `benchmarks/mini_swe_agent.py` |
| `tasks/` | the task generator (harbor adapter, template); `exp tasks` fetches the tasks the paper used from the harbor-datasets registry by default and uses this generator only with `--source adapter`: `README.md`, `adapter_metadata.json`, `build_task_image.sh` (a prebuilt task image for backends that cannot build one, e.g. eidf; set `RG_TASK_IMAGE` in `.env`), `easy.yaml`, `hard.yaml`, `parity_experiment.json`, `pyproject.toml`, `src/`, `uv.lock` |
| `splits/` | test / train task lists and, for RL, the learning band: `band.json`, `test.txt` |
| `pools/` | one SFT pool per setting, `<setting>.jsonl`: 7 files, listed below |
| `build/` | the scripts that build the pools, the rehearsal tasks and the RL band from exp's runs: `build_band.py`, `build_pools.py`, `build_rehearsal.py`, `common.py`, `gen_rehearsal.py`, `goose_system_prompt.json` |

Splits: `test` (tier easy, 96 tasks, `splits/test.txt`); `test-hard` (tier hard); `train` (both tiers, for RL); `train-easy` (tier easy); `train-hard` (tier hard); `rehearsal-t2`, generated by `build/gen_rehearsal.py`.

## Settings

Each setting is one pool file, one `--pool` value, and one `arm` in `results/cells.csv`. Names follow the grammar in `results/README.md` (`<h>-only`, `3h`, `<h1>+<h2>`, `reh-<h>`, ...).

| setting | shown in tables as | rows | harness mix | built by | reported for |
|---|---|---|---|---|---|
| `base` | Base | — | — | — | gemma-3-4b-it, qwen3-4b |
| `t2-only` | Terminus-2-only | 120 | t2 120 | `build_pools.py` | gemma-3-4b-it, qwen3-4b |
| `miniswe-only` | mini-swe-only | 114 | miniswe 114 | `build_pools.py` | gemma-3-4b-it, qwen3-4b |
| `goose-only` | Goose-only | 155 | goose 155 | `build_pools.py` | gemma-3-4b-it, qwen3-4b |
| `3h` | 3H | 389 | goose 155, t2 120, miniswe 114 | `build_pools.py` | gemma-3-4b-it, qwen3-4b |
| `miniswe+goose` | Cross-task (miniswe+goose) | 269 | goose 155, miniswe 114 | `build_rehearsal.py` | qwen3-4b |
| `reh-t2` | Rehearsal (t2) | 120 | rgt2-drill 120 | `build_rehearsal.py` | qwen3-4b |
| `miniswe+goose+reh-t2` | Cross-task + rehearsal | 389 | goose 155, rgt2-drill 120, miniswe 114 | `build_rehearsal.py` | qwen3-4b |

Evaluated without a pool of their own: `grpo-3h` (qwen3-4b); `grpo-miniswe` (qwen3-4b); `grpo-miniswe-step5` (qwen3-4b); `teacher` (qwen3-32b).

## Run

```bash
uv run exp tasks -b reasoning_gym --split test
uv run exp sft   -b reasoning_gym --pool 3h
setsid uv run exp serve -b reasoning_gym --pool 3h --port 8000 & SERVER=$!
uv run exp wait --api-base http://127.0.0.1:8000/v1 --pid $SERVER
uv run exp eval  -b reasoning_gym --pool 3h --harness all
uv run exp stop --pid $SERVER
```

## GRPO

From the `3h` SFT checkpoint, on the learning band `splits/band.json` (rebuilt exactly by `build/build_band.py` from the probe runs). `--rollout 3h` rolls out on `t2`, `miniswe`, `goose` for 1 epoch; a single harness runs 3 epochs, so both see the same number of rollouts. Shared recipe: `configs/rl.yaml`.

```bash
uv run exp tasks -b reasoning_gym --split train
uv run exp sft   -b reasoning_gym --pool 3h        # the starting checkpoint (or pass --init <path>)
uv run exp grpo  -b reasoning_gym --rollout 3h
uv run exp grpo  -b reasoning_gym --rollout miniswe
```

## Building the pools from scratch

The shipped pools are what the paper trained on; these commands rebuild them from new runs. Traces land in `runs/jobs/reasoning_gym/<job>`, pools in `runs/pools/reasoning_gym/<setting>.jsonl` (train on one with `uv run exp sft -b reasoning_gym --pool <setting> --data <file>`).

```bash
uv run exp tasks -b reasoning_gym --split train-easy && uv run exp tasks -b reasoning_gym --split train-hard
setsid uv run exp serve -b reasoning_gym --teacher --port 8000 & SERVER=$!   # the qwen3-32b teacher (2 GPUs)
uv run exp wait --api-base http://127.0.0.1:8000/v1 --pid $SERVER
uv run exp collect -b reasoning_gym                         # teacher-easy-t2, teacher-easy-miniswe, teacher-easy-goose, teacher-hard-t2, teacher-hard-miniswe, teacher-hard-goose
uv run exp stop --pid $SERVER
uv run exp tasks -b reasoning_gym --split rehearsal-t2
uv run exp collect -b reasoning_gym --rehearsal --job rehearsal-t2   # serve the 3h SFT checkpoint first
uv run exp build-pool -b reasoning_gym                      # every setting below, in order
uv run exp build-pool -b reasoning_gym --pool <setting>      # or one
```

Which script writes which setting is in the table above (config `build:`); each script's docstring describes its selection rule.
