# MedAgentBench

Training harnesses: `parity`, `t2`, `fc`; held out: `xml`. Evaluation uses four attempts per task (`n4-T0.7`), reports the trial-pooled mean, and bootstraps over tasks. Serving uses `max-model-len=32768`, the Hermes tool-call parser, and the DeepSeek-R1 reasoning parser.

- This benchmark includes the main harness comparison, rehearsal experiments for `t2` and `fc`, volume-matched datasets, a Gemma-3-4B-it replication, and GRPO.
- The Qwen3-32B teacher's evaluation results come from a corrected rerun with the reasoning parser enabled. In the earlier run, reasoning output was not parsed correctly and turns were recorded as having no action; `results/cells.csv` keeps those results, marked `superseded`.
- For the 61 test tasks, the adapter output matches the Harbor datasets registry except for author metadata.
- Gemma-3-4B-it used the same shared distillation datasets, plus its own `-gemma` rehearsal datasets and `parity+reh-t2`. The shared datasets had identical messages; only `meta` differed, which the trainer ignores. Its `parity+t2` dataset contained the same 215 rows in a different order.

Configuration: `configs/benchmarks/medagentbench.yaml`. Published results are in `results/cells.csv` with `benchmark=medagentbench`.

## Layout

| directory | contents |
|---|---|
| `harnesses/` | the agents for every harness and the `DispatchAgent` that picks one per trial (the `import_path` in the config): `funcs_v1.json`, `harness_dispatch.py`, `medagentbench_fc_agent.py`, `medagentbench_parity_agent.py`, `medagentbench_trainable_agent.py`, `medagentbench_xml_agent.py` |
| `tasks/` | the task generator (harbor adapter, template, vendored upstream data); run through `exp tasks`: `README.md`, `adapter.py`, `adapter_metadata.json`, `medagentbench.yaml`, `parity_experiment.json`, `refsol_pkg/`, `run_adapter.py`, `template/` |
| `splits/` | test / train task lists and, for RL, the learning band: `band.json`, `test.txt` |
| `pools/` | one SFT pool per setting, `<setting>.jsonl`: 21 files, listed below |
| `build/` | the scripts that build the pools, the rehearsal tasks and the RL band from exp's runs: `build_band.py`, `build_pools.py`, `build_rehearsal.py`, `build_rehearsal_fc.py`, `build_volmatched.py`, `common.py`, `gen_rehearsal.py` |

Splits: `test` (61 tasks, `splits/test.txt`); `train` (every non-test task: 215 generated; the as-run split had 209); `rehearsal-t2` and `rehearsal-fc`, generated by `build/gen_rehearsal.py --harness t2` and `--harness fc`.

## Run

```bash
uv run exp tasks -b medagentbench --split test
uv run exp sft   -b medagentbench --pool 3h
setsid uv run exp serve -b medagentbench --pool 3h --port 8000 & SERVER=$!
uv run exp wait --api-base http://127.0.0.1:8000/v1 --pid $SERVER
uv run exp eval  -b medagentbench --pool 3h --harness all
uv run exp stop --pid $SERVER
```

## GRPO

From the `3h` SFT checkpoint, on the learning band `splits/band.json` (rebuilt exactly by `build/build_band.py` from the probe runs). `--rollout 3h` rolls out on `parity`, `t2`, `fc` for 1 epoch; a single harness runs 3 epochs, so both see the same number of rollouts. Shared recipe: `configs/rl.yaml`.

```bash
uv run exp tasks -b medagentbench --split train
uv run exp sft   -b medagentbench --pool 3h        # the starting checkpoint (or pass --init <path>)
uv run exp grpo  -b medagentbench --rollout 3h
uv run exp grpo  -b medagentbench --rollout parity
```

The paper's GRPO runs may have started from an earlier version of the 3H checkpoint: the original launch script defaulted to an older 3H dataset, and the command actually used was not recorded. `exp grpo` starts from the checkpoint trained on the shipped `pools/3h.jsonl`, which is also the dataset behind the paper's 3H SFT results.

## Building the pools from scratch

The shipped pools are what the paper trained on; these commands rebuild them from new runs. Traces land in `runs/jobs/medagentbench/<job>`, pools in `runs/pools/medagentbench/<setting>.jsonl` (train on one with `uv run exp sft -b medagentbench --pool <setting> --data <file>`).

```bash
uv run exp tasks -b medagentbench --split train
setsid uv run exp serve -b medagentbench --teacher --port 8000 & SERVER=$!   # the qwen3-32b teacher (2 GPUs)
uv run exp wait --api-base http://127.0.0.1:8000/v1 --pid $SERVER
uv run exp collect -b medagentbench                         # teacher-parity, teacher-t2, teacher-fc
uv run exp stop --pid $SERVER
uv run exp tasks -b medagentbench --split rehearsal-t2
uv run exp tasks -b medagentbench --split rehearsal-fc
uv run exp collect -b medagentbench --rehearsal --job rehearsal-t2   # serve the 3h SFT checkpoint first
uv run exp collect -b medagentbench --rehearsal --job rehearsal-t2-32b   # serve the Qwen3-32B teacher first
uv run exp collect -b medagentbench --rehearsal --job rehearsal-fc   # serve the 3h SFT checkpoint first
uv run exp collect -b medagentbench --rehearsal --job rehearsal-fc-gemma   # serve Gemma's 3h SFT checkpoint first
uv run exp build-pool -b medagentbench                      # every setting below, in order
uv run exp build-pool -b medagentbench --pool <setting>      # or one
```

Which script writes which setting is in the table above (config `build:`); each script's docstring describes its selection rule.
